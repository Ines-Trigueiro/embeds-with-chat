# Changing an embed's language creates a translation, not a reader-facing switcher

When the journalist changes an embed's language and the embed already has a version, the editor asks for confirmation. It then runs one model turn that the journalist didn't type: rewrite the current version's reader-facing text into the new embed language. The result is a new immutable version (ADR 0003). It goes through the quality check like any other, and it shows in the conversation as a marker rather than a journalist message, so later turns build on the translated version. Dataset values are never translated, because the server injects them verbatim (ADR 0002). Only text the model wrote changes, and number and date formats are adapted to the new language.

We rejected a reader-facing language switcher inside the embed. An article has one audience, so a switcher adds nothing for readers. It would roughly triple every version's text and model output, and it would turn "embed language" from one choice per embed into a set of languages with a default. We also rejected silently re-labelling the existing version, because versions are immutable and the journalist must review the translated text before publishing it.
